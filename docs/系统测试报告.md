## 3. 测试类型与执行方式

### 3.1 单元测试（后端）

```bash
go test ./... -short -count=1
go vet ./...
```

**覆盖较充分的域（相对）**：

- `internal/service/alert`：路由、投递、Webhook、时序、Redis state 等  
- `internal/plugingate`：路径/菜单过滤  
- `internal/service/logplatform`：索引/保留/pipeline 等  
- `internal/pkg/mysqlbackup`：脚本与连接辅助  

**覆盖薄弱的域**：

| 域 | 现状 | 风险 |
|----|------|------|
| Auth / Casbin 中间件 | 极少 | 鉴权回归 |
| Handler 层 | 近 0 | 绑定/状态码 |
| dbmgmt 工单 FSM | 低（有 sql_guard/权限辅助测） | 审批绕过 |
| CICD 审批 E2E | 低 | 发布合规 |
| WebSocket 终端 | 无 | 会话安全 |
| 前端 | 无 | UI 门禁回归 |

近期补充：`sql_guard_test.go`、`outbound_url_guard_test.go`（核查修复）。

### 3.2 构建验证（前端）

```bash
cd web && npm ci && npm run build
```

验证 TypeScript 编译与 Vite 打包；**不包含**功能断言。

## 4. 缺陷与质量门禁

### 4.1 核查缺陷处理（摘录）

详见 `docs/yunshu-audit-report.md` §9：P0 项（CICD 审批、IDOR、sql_guard、控制台 fail-closed、CI/BOM）及部分 P1 已修复。

### 4.2 残留风险（如实）

| 项 | 说明 |
|----|------|
| 自审自批 | 产品保留 |
| JWT localStorage | XSS 可窃会话 |
| 前端无路由级 Casbin | 深链可进页，依赖后端 403 |
| Redis 告警去重 fail-open | 可能重复通知 |
| 测试覆盖不足 | 关键路径仍靠手工 |
