## 1. 启动与装配

### 1.1 进程入口

- `main.go` → CLI（`server` / `seed` / `migrate` 等，见 `cmd/`）
- 服务启动：`internal/bootstrap` 加载配置、MySQL、Redis、Casbin、日志
- HTTP：`internal/router` Wire 构建依赖 → `gin.Engine`
- 全局中间件顺序（`bootstrap`）：Recovery → RequestLogger → ErrorHandler

### 1.2 插件生命周期

| 阶段 | 调用 | 说明 |
|------|------|------|
| 迁移 | `plugin.Migrate` → 各插件 `Migrate` | 仅启用插件的表 |
| 菜单 | `menu.Sync` + `plugingate.SyncMenuVisibility` | 内置菜单与插件可见性 |
| 路由 | `plugin.RegisterRoutes` | `plugin_bind.go` switch |
| Worker | `plugin.StartWorkers` | 后台 goroutine |

## 2. 认证与会话（system）

### 2.1 类/服务

| 名称 | 文件 | 职责 |
|------|------|------|
| `AuthService` | `internal/service/system/auth_service.go` | 登录、发 token、登出、验证码 |
| `GenerateToken` | `internal/pkg/auth/jwt.go` | Claims：UserID、Username、TokenID |
| Session | `internal/store/session_redis.go` | TokenID 白名单校验 |

### 2.2 登录调用链

```
Handler.Login
  → AuthService.Login（校验用户/密码）
  → issueLoginResponse
      → auth.GenerateToken
      → Redis Set AccessTokenKey(tokenID)
      → 返回 JWT + 用户信息
```

### 2.3 Auth 中间件

`middleware.Auth`：

1. 解析 Bearer  
2. `ValidateAccessTokenSession`（Redis 失败则拒绝，**失败关闭**）  
3. 加载用户与角色写入 Context  

WS：`middleware.WSAuth` 校验并消费一次性 ticket（`store/ws_ticket`）。

## 3. 授权（Casbin / 项目 / 资源）

### 3.1 Casbin

| 组件 | 路径 |
|------|------|
| 模型 | `configs/casbin_model.conf` |
| 存储 | GORM Adapter → `casbin_rule` |
| 中间件 | `middleware/casbin.go` `Authorize` |
| 主体 | `user:<id>`；`super-admin` 旁路 |

特殊：K8s 只读 GET 可在 Casbin 拒绝后回退集群授权档位（`allowReadByK8sClusterGrant`）。

### 3.2 项目成员

`middleware/project_access.go` `RequireProjectMemberAccess`：

- `:id` 为空 → 400（禁止放行）
- GET：任意成员；非 GET：readonly 禁止
- 项目元数据变更 / 成员管理：需 admin/owner

### 3.3 资源 ACL

| 资源 | 表 | 断言 |
|------|-----|------|
| 服务器 | `server_access_grants` | `cmdb` 包 Effective/Assert |
| CICD 服务 | `cicd_access_grants` | `AssertCicdAccess(need)` |
| 库表 | `db_access_grants` | `GetEffectivePermission` / `sql_guard` |

`projectacl.FullAccess`：超管或项目 admin/owner → 资源全开。

## 4. CMDB 终端详细设计

```
前端 ServerConsolePage
  → getMyServerAccess（fail-closed）
  → openAuthenticatedWebSocket
      → POST /auth/ws-ticket
      → WS /projects/:id/servers/:serverId/terminal/ws
  → 后端 WSAuth + Authorize + ProjectMember + 执行权限校验
```

## 5. CI/CD 详细设计

### 5.1 核心类型

| 类型 | 表 | 说明 |
|------|-----|------|
| `CicdService` | `cicd_services` | 应用服务 |
| `CicdBuildRun` | `cicd_build_runs` | 构建记录 |
| `CicdReleaseRun` | `cicd_release_runs` | 发布工单 |
| `CicdReleaseApprovalStep` | `cicd_release_approval_steps` | 审批节点 |

服务：`internal/service/cicd.Service`。

### 5.2 审批状态机（摘要）

```
pending_approval →（全部步骤通过）→ pending_execution
                 →（驳回）→ rejected
pending_execution →（提交人执行）→ running → success/failed
                 →（提交人终止）→ cancelled
```

- 有步骤：`userCanApproveStep`（用户组）  
- 无步骤：`assertLegacyReleaseReviewer` → 仅 `FullAccess`  
- 详情/日志：`AssertCicdAccess(..., "view")`

### 5.3 Jenkins 同步

`RunSyncWorker` 按 `cicd.run_sync_interval_seconds` 拉取构建/发布状态写回。

## 6. dbmgmt 详细设计

### 6.1 SQL 风险守卫

文件：`internal/service/dbmgmt/sql_guard.go`

- `AssessSQL` / `AssessSQLForWrite`  
- 阻断：`DROP DATABASE`、`GRANT/REVOKE`、多语句（非 inception）等  
- 只读：`SELECT/SHOW/...`；**WITH 体含写关键字 → 高危**；`INTO OUTFILE` → 阻断  

### 6.2 工单

| 服务方法 | 行为 |
|----------|------|
| 提交 SQL 工单 | 初始化审批步骤；无启用阶段则拒绝 |
| Approve/Reject | 校验用户组；更新步骤与状态 |
| Execute | goInception（MySQL） |

元数据范围：`metadata_acl.go`（空 `database_name` → `allDatabases`，非 manage 级 unrestricted）。

## 8. K8s 详细设计

- 集群凭证加密存储（`k8s` crypto 相关 service）  
- 资源操作经 Kom/client-go 封装于各 `K8s*Service`  
- Scope：集群 grant 档位 + allow/deny NS 规则  
- Event Forward：独立 manager，写 `k8s_forwarded_events` 并可通知
