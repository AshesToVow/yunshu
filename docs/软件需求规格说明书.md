## 1. 引言

### 1.1 目的

本文档定义 Yunshu 平台的功能范围、角色、业务约束与验收标准，作为开发、测试与甲方验收的统一依据。  
**所有需求条目均对应仓库中已实现能力；未实现能力列入「不在交付范围」。**

### 1.2 产品定位

Yunshu 是面向 DevOps / SRE / 运维与研发协作的 **企业级运维管理平台**，以 **编译期插件**（`plugins.enabled`）组织能力，统一提供：

- 身份认证与 Casbin RBAC
- 多项目租户与资源 ACL
- Kubernetes 多集群管控
- 告警订阅与多渠道通知
- 日志平台（Loggie → Elasticsearch）
- 数据库变更治理（dbmgmt）
- CI/CD（Jenkins + 审批发布）
- MySQL 备份、巡检（inspect）等运维能力

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 插件 | `internal/plugins/*`，由 `configs/config.yaml` → `plugins.enabled` 控制启停 |
| Casbin | API 级 RBAC，策略存 `casbin_rule` |
| 项目角色 | `project_members.role`：owner / admin / member / readonly |
| 资源 ACL | `server_access_grants` / `cicd_access_grants` 等按资源授权 |
| goInception | MySQL SQL 审核/执行外部组件（dbmgmt） |

### 1.4 参考代码与文档

- 插件注册：`internal/plugins/all/all.go`、`internal/router/plugin_bind.go`
- 需求手册：`docs/handbook/requirements/`
- 核查报告：`docs/yunshu-audit-report.md`

## 2. 总体描述

### 2.1 用户角色

| 角色 | 来源 | 能力概要 |
|------|------|----------|
| 超级管理员 | 角色编码 `super-admin` | 跳过 Casbin / 项目成员限制（中间件实现） |
| 平台管理员 | Casbin 策略 | 用户/角色/菜单/字典/审计等系统管理 |
| 项目 owner/admin | `project_members` | 成员管理、资源授权、多数写操作 |
| 项目 member | `project_members` | 需资源 ACL / 库表授权后方可操作对应资源 |
| 项目 readonly | `project_members` | 只读；非 GET 被项目中间件拒绝 |
| 审批人 | 用户组 + 审批流阶段 | CICD / dbmgmt 工单审批 |
| 匿名 | — | 仅登录/注册/验证码；Alertmanager Webhook（Token） |

### 2.2 运行环境（与代码/配置一致）

| 层级 | 技术 |
|------|------|
| 后端 | Go 1.25、Gin、GORM、Google Wire |
| 前端 | React 18、TypeScript、Ant Design 5、Vite |
| 数据 | MySQL（业务库）、Redis（Session/告警状态） |
| 可选中间件 | Elasticsearch、Kafka、Jenkins、MinIO、Harbor、goInception、Prometheus/Alertmanager |
| 部署 | Docker Compose（`docker-compose.yml`）、镜像 `Dockerfile.backend` / `web/Dockerfile.frontend` |

### 2.3 插件能力矩阵（交付范围）

配置默认启用（`configs/config.yaml`）：

| 插件 ID | 业务目标 | 主要路由注册 |
|---------|----------|--------------|
| `core` | 认证、用户/角色/权限/菜单/字典/部门/审计 | `RegisterCoreRoutes` |
| `project` | 项目/成员/服务/日志检索/Loggie | `RegisterProjectRoutes` + `RegisterLogPlatformRoutes` |
| `cmdb` | 服务器/分组/云账号/SSH 终端 | `RegisterCMDBRoutes` |
| `k8s` | 多集群资源、Helm、事件转发、K8s 策略 | `RegisterK8sRoutes` |
| `alert` | 告警渠道/规则/订阅/值班/静默/云到期 | `RegisterAlertRoutes` |
| `backup` | MySQL 备份实例与任务 | `RegisterBackupRoutes` |
| `cicd` | Jenkins 构建/发布与审批 | `RegisterCicdRoutes` |
| `dbmgmt` | 库实例、SQL 查询/工单、授权 | `RegisterDbmgmtRoutes` |
| `inspect` | 巡检计划/执行/报告 | `RegisterInspectRoutes` |

关闭插件后：对应路由不注册，菜单经 `plugingate.SyncMenuVisibility` 隐藏。

## 3. 功能需求

### 3.1 R-CORE 认证与系统管理

| 编号 | 需求 | 实现位置 | 验收要点 |
|------|------|----------|----------|
| CORE-01 | 用户名/密码登录，签发 JWT | `AuthService.Login` | 返回 token；Redis 存 session |
| CORE-02 | 邮箱验证码登录 | `AuthService.EmailLogin` | 依赖邮件配置 |
| CORE-03 | 登出使 session 失效 | `AuthService.Logout` | Redis key 删除后请求 401 |
| CORE-04 | 用户 CRUD、导入、角色绑定 | `UserService` | Casbin 同步 |
| CORE-05 | 角色/权限/策略管理 | `RoleService` / `PermissionService` / `PolicyService` | 策略写入 Casbin |
| CORE-06 | 菜单树与菜单权限绑定 | `MenuService` + `menu.Sync` | 与内置 `menu/catalog.go` 同步 |
| CORE-07 | 部门树 | `DepartmentService` | |
| CORE-08 | 字典项（含敏感值 reveal） | `DictEntryService` | Casbin 控制 |
| CORE-09 | 登录日志 / 操作审计 | `LoginLogService` / `OperationLogService` | 写操作经 `OperationAudit` 中间件 |
| CORE-10 | 注册申请审批 | `RegistrationService` | 有限流 `RegistrationRateLimit` |
| CORE-11 | WebSocket 一次性 ticket | `POST /auth/ws-ticket` | 终端/Pod Exec 使用 |

### 3.2 R-PROJECT 项目与日志

| 编号 | 需求 | 实现位置 | 验收要点 |
|------|------|----------|----------|
| PRJ-01 | 项目 CRUD、成员角色 | `project` 包 | 成员唯一约束 |
| PRJ-02 | 项目成员中间件隔离 | `RequireProjectMemberAccess` | 非成员 403；readonly 禁写 |
| PRJ-03 | 服务配置 / 服务目录 | `Service` / `ServiceCatalog` | |
| PRJ-04 | 日志检索与导出 | `LogSearchService` | 依赖 ES 配置 |
| PRJ-05 | Loggie 安装/心跳/启停 | `LoggieAgentService` | 离线二进制 `deploy/loggie/binary` |
| PRJ-06 | 日志保留策略调度 | `RunLogRetentionScheduler` | project 插件 worker |
| PRJ-07 | Kafka→ES（可选） | `KafkaToESService.Run` | `kafka.enabled` |

**说明**：日志采集路径为 **目标机 Loggie → Elasticsearch**；后端提供引导/心跳/检索，**无独立业务机采集端口**。

### 3.3 R-CMDB 服务器资产

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| CMDB-01 | 服务器/分组/凭据/云账号 | 项目作用域 |

## 4. 非功能性需求

| 类别 | 要求 | 代码依据 |
|------|------|----------|
| 安全 | JWT + Redis Session 失败关闭 | `middleware/auth.go` |

| 安全 | 出站告警 URL 禁止 localhost/元数据 | `outbound_url_guard.go` |
| 审计 | 写操作审计日志 | `OperationAudit` |

| 可观测 | slog 多文件日志 | `docs/logging.md` |
| 可用性 | 健康检查 | `GET /api/v1/health` |

### 4.1 明确不在本版本交付范围

- MFA / OAuth2 / SSO
- 移动端 App
- GitLab CI 原生集成（交付为 Jenkins）
- 前端自动化测试框架（当前 `web/` 无 Vitest/Playwright）
- goInception 对 PostgreSQL / SSH 隧道审核
- 完整 K8s 原生部署 Yunshu 自身（仓库 `deploy/k8s` 主要为集群组件样例；Yunshu 应用以 Compose 为主）

## 5. 接口与数据需求（摘要）

- **统一前缀**：`/api/v1`
- **鉴权**：`Authorization: Bearer <JWT>`；WS 使用 ticket
- **响应**：`internal/pkg/response` 统一 Success/Error
- **Swagger**：配置 `swagger.enabled`；路由 OpenAPI 可由 `tools/genopenapi` 生成
- **数据**：GORM AutoMigrate，按插件迁移（`bootstrap.AutoMigrateModels`）

详见《API接口设计说明书》《数据库设计说明书》。

## 6. 验收标准总表

| 域 | 必验项 |
|----|--------|
| 登录 | admin 首次 seed 可登录；错误密码失败；登出后 token 失效 |
| 权限 | 无策略用户访问受保护 API 返回 403 |
| 项目 | 非成员无法访问 `/projects/:id/*` |
| CMDB | 无执行授权不可终端/exec |
| CICD | 无服务授权不可读详情日志；无审批流时普通成员不可审批 |
| dbmgmt | 无授权不可查；写操作走工单；空审批流不可提交 |
| 告警 | Webhook Token 错误拒绝；渠道可投递（依赖外部可达） |
| 插件 | 关闭某插件后对应 API 404/未注册、菜单不可见 |
| 部署 | `docker-compose` 可起 backend+frontend+redis；`/api/v1/health` 正常 |
