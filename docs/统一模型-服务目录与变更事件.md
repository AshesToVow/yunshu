# 统一模型：服务目录与变更事件

服务目录与变更流水地基说明（变更中心 / 故障工作台已下线）。

## 三件套

| 能力 | 作用 |
|------|------|
| **插件契约（Manifest）** | 后端 `plugin.Manifest` + `GET /api/v1/plugins` 为菜单路径 / API 前缀的单一事实源 |
| **服务目录（service_catalog）** | 项目级稳定 `service_id`；`service_links` 关联各域实体 |
| **变更事件（change_events）** | 写操作汇入统一时间线，供服务画像「最近变更」等聚合 |

## 产品能力

| 能力 | 入口 | 说明 |
|------|------|------|
| **服务画像** | `/service-portrait` | 聚合 links、入口、最近变更、CI/CD 摘要、健康分 |
| **K8s 治理** | preview-apply / snapshots | dry-run 文本 diff、impact、变更前快照回滚 |
| **发布后验证** | CI/CD 详情 Tab | Ready + 日志弱信号 + 新告警，写回 `verify_status` |

## 其它治理

### K8s 保护

- `POST /deployments/preview-apply`（StatefulSet 同路径）
- `GET /deployments/snapshots`、`POST /deployments/snapshots/rollback`
- Apply/Delete 前快照写入 `k8s_workload_snapshots`

### 发布验证

- `POST /projects/:id/cicd/release-runs/:runId/verify`
- 字段：`cicd_release_runs.verify_status` / `verify_json` / `verified_at`

### 告警质量

- `GET /api/v1/alerts/quality-report`
- 菜单：`/alert-quality`

### 关键 API 摘要

```
POST /api/v1/projects/:id/cicd/release-runs/:runId/verify
POST /api/v1/deployments/preview-apply
GET  /api/v1/deployments/snapshots
POST /api/v1/deployments/snapshots/rollback
GET  /api/v1/alerts/quality-report
```

## 数据关系

```
project
  ├── service_catalog → service_links
  ├── change_events
  └── (via owning_project) k8s_workload_snapshots
```

## 写入约定

- CI/CD 服务 upsert → 自动目录 + `cicd_service` link
- 变更埋点：CI/CD release；K8s apply/scale/restart/delete/rollback；dbmgmt SQL；alert 维护窗
